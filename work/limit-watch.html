Work/07

Limit Watch

A Windows tray app for a one-week test. Every 3 seconds it reads the window in front, and a model on my PC decides whether I just hit an AI usage limit and when it resets.

01Problem

Hitting a usage limit mid-task means guessing when it resets and remembering to come back.

02What I built

  • A local model that spots limit messages, with its answer and the reset time checked in code.
  • It can paste a held message when the limit resets, but only where I chose "Send it for me" and only into the window the limit appeared in.

03How it was tested

  • Unit tests.
  • End-to-end tests with and without the real model.
  • A held-out set of real limit messages and look-alikes.

04Results

Measured results.
CheckResult
Unit tests370/370
End-to-end74/74
End-to-end with the real model76/76
Held-out limit messages caught13/20
False alarms2/30
Limit messages printed in a terminal caught2/7

I chose few false alarms over catching terminal messages: a version that caught more flagged about half of the terminal look-alikes.

Changing how the model is asked cut false alarms on 54 look-alikes from 8 to 2.

05What I learned

How you ask a model matters as much as which model you use, and its answer should still be checked in code.
